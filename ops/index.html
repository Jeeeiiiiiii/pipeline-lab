A deployment is an operation. The sign-in checks (scans) each say GO or NO-GO; a NO-GO stops everything after it. The procedure ships the image and rolls it out; sign-out attacks it and files the reports. On the right the app is the patient on a bedside monitor: its error rate, and the alert that fires when more than 5% of requests fail for a full minute.

The trace is 5xx ÷ all requests over a 1-minute window, the exact expression the alert evaluates, sampled every 10 s from Prometheus. Above the dashed 5% line the alert goes pending; it must stay above for its for: 1m before it fires. Requests go straight to the app's Service through the Kubernetes API (no ingress), so they count in the same metric.

Stage scripts run with docker compose -f runner/docker-compose.yml run --rm toolbox; the GitHub → runner hop itself has not run (no remote yet). The monitor reads the cluster through kubectl proxy on .cluster/kubeconfig.yaml. A full procedure pushes a new tag, upgrades the Helm release and writes reports to S3.
